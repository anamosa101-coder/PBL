Belady's Anomaly Test Lab

Demonstrates how increasing frame allocation under FIFO can paradoxically increase page faults.

📁 FIFO (First-In, First-Out)

Simple queue-based eviction. Evicts the page resident in memory the longest. Prone to Bélády's Anomaly where adding frames may increase page faults.

🕒 LRU (Least Recently Used)

Evicts the page that hasn't been accessed for the longest time in the past. Requires hardware support (timestamps or stack) and belongs to the class of stack algorithms.

🔮 Optimal (Bélády's OPT)

Evicts the page that will not be used for the longest period in the future. Serves as the theoretical benchmark (lowest faults), but impossible to implement in real OS.

Operating Systems Viva Cheat Sheet

Key concepts, formulas, and oral defense questions for college OS PBL presentations.

1. What triggers a Page Fault?

A page fault occurs when a process attempts to access a virtual memory page that is currently not mapped into physical RAM (valid-invalid bit is 0 in the page table).

2. What is Belady's Anomaly?

A phenomenon in FIFO where increasing the number of physical memory frames leads to an increase (rather than decrease) in the number of page faults. Stack algorithms like LRU and OPT are immune.

3. Why can't Optimal be used in production OS?

Because it requires future knowledge of the process's page reference string, which cannot be predicted deterministically. It is used as an ideal upper-bound benchmark.

4. Performance Metric Formulas

Hit Ratio (%) = (Hits / (Hits + Faults)) × 100
Fault Ratio (%) = (Faults / (Hits + Faults)) × 100
Hit Ratio + Fault Ratio = 100%
